# **Component Specification: RichContent**

## **1. Component Name**

**`RichContent`**

## **2. Description**

A component for safely rendering HTML content generated by the Lexical editor.

* Renders rich text including headings, paragraphs, lists, links, code blocks, and inline formatting
* Preserves all formatting from the Lexical editor output
* Provides consistent typography styling across all rendered elements
* Used wherever Lexical-generated content needs to be displayed

## **3. Location**

```
src/components/ui/RichContent/RichContent.tsx
```

## **4. Component Type**

**UI** – Stateless presentational component for rendering HTML content.

## **5. Props Interface**

```typescript
interface RichContentProps {
  content: string;
  className?: string;
}
```

## **6. Props**

| Prop | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| `content` | `string` | Yes | - | HTML string from Lexical editor |
| `className` | `string` | No | `''` | Additional CSS class for styling |

## **7. Data Requirements**

### **External Data Sources**

* HTML content string passed via props (typically from database/API)

### **Content Format**

HTML string generated by the Lexical editor, which may contain:

* Headings (`h1` - `h6`)
* Paragraphs (`p`)
* Ordered lists (`ol`) and unordered lists (`ul`)
* Links (`a`), including mention links
* Code blocks (`pre`, `code`)
* Blockquotes (`blockquote`)
* Inline formatting (bold, italic, underline, strikethrough)

## **8. Internal State**

| State Variable | Type | Purpose |
|----------------|------|---------|
| - | - | No internal state – stateless component |

## **9. Behaviour Matrix**

| Condition / State | UI Rendered | Notes |
|-------------------|-------------|-------|
| Valid HTML content | Formatted HTML with styling | All elements styled via CSS module |
| Empty string | Empty div | No visible content |
| Content with headings | Styled heading hierarchy | h1-h6 with appropriate sizes |
| Content with lists | Styled bullet/numbered lists | Proper indentation |
| Content with code | Monospace styled code blocks | Syntax highlighting if configured |
| Content with links | Clickable styled links | Default link styling |
| Content with mentions | Styled mention links | `a.mention-link` class |

## **10. Dependencies**

### **Child Components**

* None

### **Utilities / Hooks**

* None

### **Directives**

* `'use client'` – Client component for DOM rendering

## **11. Events & Callbacks**

| Event / Callback | Trigger | Description |
|------------------|---------|-------------|
| - | - | No events – static content rendering |

*Links within content use standard browser navigation.*

## **12. Styling**

* **Approach**: CSS Modules with SCSS
* **File**: `RichContent.module.scss`

### **Visual States**

* **Default**: Styled typography for all HTML elements
* **Links**: Styled anchor tags with hover states
* **Code**: Monospace font with background
* **Blockquotes**: Indented with border styling
* **Lists**: Proper bullet/number styling with spacing

### **Styled Elements**

All standard HTML elements receive typography styling:
* Headings (h1-h6)
* Paragraphs
* Lists (ul, ol, li)
* Links
* Code blocks
* Blockquotes
* Inline formatting

## **13. Accessibility Requirements**

* **Semantic HTML**: Content maintains semantic structure from Lexical
* **Heading Hierarchy**: Preserved from source content
* **Link Text**: Inherits meaningful text from editor
* **Focus**: Links receive standard focus indicators

### **Improvements Needed**

* Ensure code blocks have appropriate `role` if not using semantic elements
* Consider `aria-label` for icon-only links if any exist in content

## **14. Error Handling**

| Error Condition | Behaviour | Fallback |
|-----------------|-----------|----------|
| Empty content | Renders empty div | No visible output |
| Malformed HTML | Browser's HTML parser handles | May render unexpectedly |
| Missing content prop | Component won't render properly | Required prop |

### **Security Note**

Content should be sanitized before storage. The Lexical editor produces safe HTML, but any external content should be sanitized server-side before passing to this component.

## **15. Performance & Lifecycle Notes**

* **Re-renders**: Only when `content` or `className` props change
* **DOM**: Uses `dangerouslySetInnerHTML` for direct HTML injection
* **No Effects**: No side effects or cleanup needed

## **16. Usage Examples**

### **Basic Usage**

```tsx
import { RichContent } from '@/components/ui/RichContent';

<RichContent content={post.content} />
```

### **With Custom Styling**

```tsx
<RichContent
  content={discussion.body}
  className="discussion-body"
/>
```

### **In Post Display**

```tsx
<article className={styles.post}>
  <h1>{post.title}</h1>
  <RichContent content={post.content} />
</article>
```

## **17. Features Summary**

* HTML rendering via dangerouslySetInnerHTML
* Full Lexical formatting preservation
* Consistent typography styling for all elements
* Simple two-prop interface
* CSS module styling with className override support

## **18. Testing Considerations**

### **Unit Tests**

* Renders content prop as HTML
* Applies base styles class
* Applies additional className when provided
* Handles empty content gracefully

### **Mocking**

* No mocking required – pure render component

### **Edge Cases**

* Empty string content
* Content with only whitespace
* Content with all supported HTML elements
* Very long content
* Content with deeply nested elements

## **19. Out of Scope / Non-Goals**

* **Content sanitization**: Must be done server-side before storage
* **Interactive elements**: No event handling within rendered content
* **Mention hover cards**: Use `RichContentWithMentions` instead
* **Syntax highlighting**: Not included; add via CSS or separate library
* **Content editing**: Read-only display only
